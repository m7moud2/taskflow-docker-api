المستوى الرابع • هندسة الشبكات والـ DNS الداخلي

🌐 شبكات دكر المعزولة والـ Embedded DNS Engine

كيف تتبادل الحاويات البيانات باسم الخدمة (Service Name) بدلاً من كتابة الـ IP المتغير؟

network: taskflow_network (Driver: bridge)

Docker DNS: 127.0.0.11
📌 Nginx -> App Resolution
Nginx يرسل الطلب إلى http://app:3000. محرك الـ Embedded DNS في Docker يترجم الكلمة app إلى IP الحاوية الداخلي تلقائياً (مثلاً 172.20.0.3).
📌 App -> Postgres Resolution
تطبيق Express يتصل بـ PostgreSQL بـ Connection String: postgres://user:pass@postgres:5432/db. لا حاجة لمعرفة IP السيرفر!
📌 App -> Redis Resolution
تطبيق Express ينشئ اتصال Redis باستخدام العنوان: redis://redis:6379 ويقوم بعمل Ping/Pong بسرعة متناهية.
المستوى الخامس • التشريح البرمجي الكامل

🔍 تفكيك Dockerfile الشامل (سطر بسطر وحرف بحرف)

الشرح الفعلي والسبب الهندسي الخفي وما يحدث لو قمت بإزالة كل سطر مع مقارنة البناء متعدد المراحل Multi-Stage.

FROM node:22-alpine AS builder
📌 معنى السطر:
بدء مرحلة البناء (Stage 1) باستخدام صورة Alpine خفيفة جدًا (حجمها 5MB) مجهزة بـ Node.js 22 وتسميتها باسم مستعار `builder`.
🤔 ليه كتبت كدا؟
لبناء كود TypeScript وتجميعه إلى JavaScript نقي في بيئة معزولة تترك كل أدوات البناء التابعة لـ `devDependencies` بعيداً عن التشغيل النهائي.
⚠️ لو شلته؟
فتك كامل بالبناء وعدم وجود محرك Node أو بيئة تجميع TypeScript.
WORKDIR /app
📌 معنى السطر:
تحديد المجلد المستهدف للعمل داخل الحاوية إلى `/app`.
🤔 ليه مش في الـ root؟
لمنع خلط ملفات المشروع مع ملفات نظام التشغيل النظامية في `/` وتسهيل التعامل المساري.
COPY package*.json tsconfig.json ./
📌 معنى السطر:
نسخ ملفات تعريف المكتبات ومسببات التجميع فقط أولاً إلى المجلد الحالي.
🤔 ليه قبل الكود الأصلي؟
لتحقيق Docker Layer Caching وعدم تكرار تثبيت المكتبات بـ `npm ci` إلا لو تغيرت المكتبات في `package.json` فعلياً!
⚠️ لو نسخته مع باقي الكود؟
سيرتفع وقت البناء بشكل مزعج لأن كل تعديل بسيط في ملفات TS سيعيد تحميل كل الـ node_modules من جديد.
RUN npm ci
📌 معنى السطر:
تثبيت المكتبات بدقة متناهية مطابقة لملف `package-lock.json`.
🤔 ليه `npm ci` مش `npm install`؟
لأن `npm ci` أسرع وأكثر أماناً في بيئات البناء (CI/CD) حيث يلتزم بالنسخ المحددة بدقة بدون تحديث عشوائي للمكتبات.
COPY --from=builder /app/dist ./dist
📌 معنى السطر (في Stage 2):
نسخ نتائج التجميع فقط من مرحلة الـ `builder` إلى الحاوية النهائية المشغلة.
🤔 الفائدة العظمى؟
تخفيض حجم الصورة الحاوية النهائية من 1.1GB إلى أقل من 115MB فقط، مع استبعاد كود المصدر الأصلي وحماية الملكية الفكرية!
USER node
📌 معنى السطر:
تشغيل الحاوية بصلاحيات مستخدم عادي محدودة `node` وليس صلاحيات الجذر الفائقة `root`.
🤔 الأمان هنا؟
لمنع ثغرة الـ Container Escape، فلو تم اختراق التطبيق لن يملك الاختراق صلاحيات root على جهاز المستضيف أصلاً.

🧩 تفكيك docker-compose.yml تفصيلياً

كيف تدار الخدمات الأربعة وتتواصل في شبكة واحدة مع حفظ البيانات الدائم.

services: { app: { build: . , ports: ["3000:3000"] } }
📌 معنى السطر:
تعريف خدمة التطبيق وبنائها من Dockerfile الحالي وتوجيه المنفذ 3000.

📌 معنى السطر:
إقلاع التطبيق مشروط باجتياز فحص صحة الداتابيز فعلياً بـ Healthcheck ناجح، وليس مجرد بدء تشغيل الحاوية!
🤔 فائدته؟
يمنع خطأ "ECONNREFUSED" الناجم عن إقلاع تطبيق Node قبل تجهيز Postgres لاستقبال اتصالات الشبكة.
volumes: [ postgres_data:/var/lib/postgresql/data ]
📌 معنى السطر:
ربط مجلد بيانات Postgres بـ Named Volume دائم ومستقل لحفظ البيانات حتى عند إيقاف وإعادة بناء الحاويات.

المستوى الرابع عشر • الاستعداد للانترفيو

🎴 بطاقات الأسئلة الشائعة في المقابلات (Interview Flashcards)

اضغط على أية بطاقة لكشف الإجابة النمطية النموذجية التي تُبهر المقابلين!

❓ ما الفرق بين CMD و ENTRYPOINT في Dockerfile؟
💡 ENTRYPOINT يحدد الأمر الأساسي الثابت للحاوية، بينما CMD يقدم المعاملات الافتراضية التي يمكن استبدالها أثناء التشغيل بسهولة من التيرمينال.
❓ كيف تضمن أن الداتابيز جاهزة فعلياً قبل إقلاع تطبيق Node؟
💡 باستخدام خاصية condition: service_healthy مع الـ Healthcheck المباشر في `docker-compose.yml` بدلاً من مجرد `depends_on`.
❓ ما فائدة البناء متعدد المراحل Multi-Stage Build؟
💡 فصل بيئة التجميع الباهظة الحجم عن بيئة التشغيل النظيفة الخفيفة، مما يخفض الحجم الكلي بنسبة تزيد عن 90% ويؤمن الكود المصدري.
❓ ما الفارق بين Named Volume و Bind Mount؟
💡 الـ Named Volume تديره دكر بالكامل وتخزن بياناته في المجلد النظامي وهي الخيار الأمثل لقواعد البيانات بفضل أدائها واستمراريتها، بينما الـ Bind Mount يربط مجلداً معيناً من جهاز المطور للتطوير المباشر.
❓ كيف يمنع Redis هجمات الـ Overload على السيستم؟
💡 باستخدام خوارزمية Fixed Window / Token Bucket لزيادة العداد الذري `INCR` لكل IP وإرجاع رد `429 Too Many Requests` عند التجاوز.
❓ ما هي فائدة Nginx كـ Reverse Proxy أمام Express؟
💡 استقبال الترافيك على بورت 80 القياسي، معالجة الـ SSL/TLS Termination، ضغط الملفات بـ Gzip، حجب ثغرات WebVulns عبر الترويسات الأمنية، وتوجيه الطلبات بـ HTTP/1.1 للخدمات الداخلية.

📖 قاموس مصطلحات Docker والباك إند الشامل

Docker Image
الوصفة المجمدة المجهزة للبناء تحتوي الكود والبيئة والمكتبات.
Docker Container
النسخة الشغالة المباشرة في الذاكرة المعزولة المشتقة من الـ Image.
Reverse Proxy
خادم كوسيط يستقبل الطلبات من العملاء ويوجهها للخدمات الداخلية بـ Nginx.
Cache-Aside Pattern
استراتيجية قراءة البيانات من الكاش أولاً ثم القراءة من الداتابيز عند عدم الوجود.
Layer Caching
تقنية إعادة استخدام الطبقات غير المتغيرة في دكر لتوفير وقت إعادة التجميع.
Healthcheck
فحص دائم ومستمر تنفذه الحاوية للتأكد من جاهزية الخدمة لاستقبال الترافيك.
